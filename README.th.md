## 🏛 โทโพโลยีของกองเรือ

ระบบรันอยู่บนสามโฮสต์ แต่ละโฮสต์เป็น **โหนดอิสระ: หนึ่งเครื่อง = หนึ่งตระกูลกลยุทธ์ =
หนึ่งบัญชีย่อย OKX** นี่ไม่ใช่ทางเลือกเชิงสไตล์ — มันคือการแก้ไขข้อบกพร่องสามข้อ
ที่พบในระบบผลิต (ดู § บทเรียน)

```
 ┌──────────────────────────────────────────────────────────────┐
 │                    EXCHANGE LAYER — OKX EEA                  │
 │         (EU keys only work against eea.okx.com)              │
 └───────┬──────────────────┬──────────────────┬────────────────┘
         │                  │                  │
 ┌───────▼────────┐ ┌───────▼────────┐ ┌───────▼──────────────┐
 │ NODE A         │ │ NODE B         │ │ NODE C               │
 │ nuvola         │ │ mc2            │ │ MARCODG1             │
 │ TREND (daily)  │ │ GRID adaptive  │ │ 4H momentum          │
 │ sub: nuvolasub1│ │ sub: mc2sub1   │ │ sub: marcosub1       │
 │ edge MEASURED  │ │ gate: to be    │ │ gate: needs fees     │
 │                │ │ measured       │ │ below 0.30%/side     │
 └────────────────┘ └────────────────┘ └──────────────────────┘
         │                  │                  │
         └──────────────────┴──────────────────┘
                            │
              ┌─────────────▼──────────────┐
              │ PORTFOLIO RISK GOVERNOR    │
              │ one budget: 2% of capital  │
              │ daily stop −3%, max DD −10%│
              └────────────────────────────┘
```

**สามกฎที่ต่อรองไม่ได้:**

1. **หนึ่งบัญชีต่อหนึ่งกลยุทธ์** ไม่มีบอทใดแชร์บัญชีย่อยกับกลยุทธ์อื่น
2. **ความเสี่ยงเป็นคุณสมบัติของพอร์ต ไม่ใช่คุณสมบัติของบอทแต่ละตัว** งบ 2% คิดจากเงินทุน*ทั้งหมด*
   บอทเจ็ดตัวที่ต่างประกาศว่าเสี่ยงทั้งบัญชี เท่ากับ **14% ของบัญชี ไม่ใช่ 2%** — วัดโดย
   `tools/audit_capitale_config.py`
3. **ไม่มีกลยุทธ์ใดเข้าสู่ระบบผลิตได้โดยไม่ผ่านประตู**: expectancy สุทธิเป็นบวก
   นอกตัวอย่าง (out-of-sample) ที่ต้นทุน*จริง*ของบัญชีที่มันรันอยู่

## 🧪 การทดสอบ — และทำไมมันจึงเป็นการแก้ไขที่ใหญ่ที่สุดของรอบนี้

```bash
python -m pytest denaro/tests -q      # 382 passed, 3 skipped
```

เป็นเวลาหลายสัปดาห์ที่ชุดทดสอบรายงาน **63 failed และ 50 errors** เกือบไม่มีข้อใดเป็น
ข้อบกพร่องของโค้ดเลย: มันเป็น**ข้อผิดพลาดเรื่องสิทธิ์ของสภาพแวดล้อม** สาเหตุราก
ที่แยกออกมาได้ด้วยการทดสอบตรง ๆ สามครั้ง:

```
os.makedirs(<repo>/.pytmp/probe) + write   -> OK
tempfile.mkdtemp()               + write   -> PermissionError
os.makedirs(...) + open(...)     -> OK
```

`tempfile.mkdtemp` ถูกปฏิเสธในขณะที่ `os.makedirs` ทำงานได้ — และทั้ง `TemporaryDirectory`
และ `tmp_path` ของ pytest ต่างก็วิ่งผ่านมัน ผลที่ตามมาคือความเสียหายจริง: **สอง session
การทำงานที่เป็นอิสระต่อกันยืนยันอะไรไม่ได้เลย** และชุดทดสอบที่ผลลัพธ์เป็นแค่สัญญาณรบกวน
ก็ปกป้องอะไรไม่ได้ `denaro/tests/conftest.py` จึงเข้ามาแทนที่มันที่ระดับราก: ผลลัพธ์เปลี่ยนจาก
*63 failed / 50 errors* เหลือ **failure จริง 1 รายการ** ซึ่งเป็นช่องว่างเชิงความหมายที่รู้อยู่แล้ว
(ดู § งานที่ยังเปิดอยู่)

## 💰 เศรษฐศาสตร์ — พูดกันตรง ๆ

ตัวเลขที่ชี้ขาดไม่ใช่กลยุทธ์ แต่คือค่าผ่านทาง วัดจากหน้าค่าธรรมเนียมทางการของ OKX EEA:

| บัญชี | maker | taker | round trip | gross edge ต่อการเทรดที่คุ้มทุน |
| :--- | :--- | :--- | :--- | :--- |
| OKX EEA **ที่ไม่มี** ดิริเวทีฟ (ปัจจุบัน) | 0.200% | **0.350%** | **0.700%** | **0.70%** |
| OKX EEA **ที่เปิด** X-Perps แล้ว | 0.080% | **0.100%** | **0.200%** | 0.20% |

การเปิดบัญชีดิริเวทีฟบน OKX EEA **ไม่** ต้องใช้ปริมาณการซื้อขายหรือเงินทุน — ต้องมีเพียง KYC
บวกกับ*การประเมินความเหมาะสม (appropriateness assessment)* เท่านั้น มันย้ายบัญชีจากตาราง
0.35% ไปยังตาราง 0.10%

**และการแก้ไขความเข้าใจผิดที่วนเวียนอยู่หลายวัน:** `−1.97%` ของ trend รายวันคือ
**alpha สะสมตลอด 2.4 ปี** ไม่ใช่ผลตอบแทนรายวัน ที่ต้นทุนศูนย์ สัญญาณนี้มีนัยสำคัญ
(t = +4.51); ที่ 0.35% ต่อข้าง มัน**แยกจากศูนย์ไม่ได้** (t = −0.30) มันไม่ใช่กลยุทธ์ที่เลือดไหล —
มันคือกลยุทธ์ที่ค่าผ่านทางลบทิ้ง

คันโยกสองอันที่ทวีคูณได้จริง:

- **ลดค่าผ่านทาง** — 0.70% → 0.20% ต่อ round trip ซึ่งทวีคูณความถี่ที่ยั่งยืนได้ 3.5 เท่า;
- **เพิ่มความถี่** — ตระกูล 4H ไปจาก 3/24 เป็น 18/24 การตั้งค่าที่ทนทาน (robust)
  ที่ค่าธรรมเนียมต่ำเดียวกัน นั่นคือโอกาสมากขึ้น ~8 เท่า

ไม่มีอันใดในสองอย่างนี้ที่เป็นโค้ด อันหนึ่งคือการประเมิน อีกอันคือผลที่ตามมา

## 🛡 การบริหารความเสี่ยง

- **ความเสี่ยงต่อการเทรด** — 2% ของเงินทุน ตรึงไว้ในไฟล์กำหนดค่าและเผยแพร่ใน health
- **เซอร์กิตเบรกเกอร์** — หยุดรายวันที่ −3%, maximum drawdown ที่ −10% คงสภาพข้ามการรีสตาร์ท
- **เพดานความเสี่ยงต่อบัญชี** — คิดจาก*ผลรวม*ของบอททั้งหมดบนบัญชีย่อยเดียวกัน ไม่ใช่ต่อบอท
- **การจำแนกสถานะเงินทุน** — โหนดที่ไม่มีเงินทุนจะประกาศ `NON FINANZIATO` ครั้งเดียวต่อ
  การเปลี่ยนสถานะ ไม่วางคำสั่งใด ๆ และไม่ทำให้ baseline ของ peak / รายวัน / รายสัปดาห์
  แปดเปื้อนเลย มันออกจากสถานะนี้ได้เองเมื่อเงินทุนเข้ามา โดยไม่ต้องรีสตาร์ท
- **Idempotency ของคำสั่ง** — ทุกครั้งที่ส่งคำสั่งมี `clOrdId` ติดไปด้วย และถูกบันทึก journal
  *ก่อน* คำสั่งจะออกไป; คำสั่งที่รอดจากการ crash จะถูกจดจำว่าเป็นของเราเมื่อรีสตาร์ท
  แทนที่จะถูกนับเป็นคำสั่งที่ไม่รู้จัก
- **ความหมายของ stop** — stop ขายเฉพาะส่วนที่บอทตัวนั้นมีสิทธิ์ (`tracked size + bought-not-resold`)
  ไม่เคยขายยอดคงเหลืออิสระของบัญชี: เมื่อมีบอทสองตัวบนบัญชีย่อยเดียว พฤติกรรมแบบเก่า
  ถึงขั้นเทขายสินค้าคงคลังของบอทอีกตัว
- **Supervisor** — แรงกดดันของ RAM/CPU หน่วงช่วงเวลา tick (`nominal` → `caution` → `safe` →
  `emergency`)

## 🔒 ความปลอดภัย — โฮสต์หนึ่งเครื่องถูกบุกรุก ตอนนี้ควบคุมไว้ได้แล้ว (2026-09-25)

การตรวจสอบกองเรือพบ **cryptominer ของบุคคลที่สาม** บน MARCODG1: ไฟล์ไบนารี ELF ใน
`/var/tmp/.X11-unix-socket/` รันในนามผู้ใช้บริการ `zabbix` เป็นเวลา **4 วัน** ใช้ CPU 199%
และ RAM 2.1 GB มีการฝังตัวผ่าน cron และมีการเชื่อมต่อกับ mining pool อยู่จริง มันเป็นสาเหตุ
โดยตรงที่โหนดเทรดจริงแกว่งไปมาระหว่าง `SafeMode safe ↔ caution` (RAM อยู่ที่ 87%)

การควบคุมสถานการณ์ โดยคัดลอกหลักฐานทางนิติวิทยาศาสตร์ไว้ **ก่อน** การลบใด ๆ:

| การดำเนินการ | ผลลัพธ์ที่ยืนยันแล้ว |
| :--- | :--- |
| ยุติโปรเซส | ไม่มี PID, การเชื่อมต่อ pool 0 รายการ |
| RAM | ใช้ไป **3114 → 1003 MB** |
| การฝังตัวผ่าน cron | ลบออกแล้ว (ตรวจสอบ spool บนดิสก์แล้ว) |
| ไฟล์ไบนารี | `chmod 000` + เก็บสำเนาไว้ใน `/root/quarantena_miner_20260925/` |
| กฎ `sudo` ที่ไม่มีเจ้าของของ `zabbix` | ลบออกแล้ว → *ไม่ได้รับอนุญาตให้รัน sudo* |
| `AllowKey=system.run[*]` | ปิดใช้งานบน**ทั้งสอง**โฮสต์ |

**เรื่องที่เจ้าของต้องจัดการต่อ:** เพิกถอน GitHub PAT ที่พบเป็นข้อความธรรมดาในประวัติเชลล์;
หมุนเวียนข้อมูลประจำตัวของ Zabbix; ตัดสินใจว่าจะสร้างโฮสต์ที่ถูกบุกรุกใหม่หรือไม่;
สร้าง key vault ใหม่ (คีย์ OKX ในนั้นตายทั้ง 7 จาก 7); ทบทวน firewall (`ufw` ไม่ทำงาน,
`5432` และ `10050` เปิดเผยอยู่)

## 📚 บทเรียน ("La Baracca")

โปรเจกต์นี้เดิมมีชื่อเล่นว่า *"La Baracca"* — ภาษาอิตาลีแปลว่าของประกอบชั่วคราวที่ต้องปะอยู่
ตลอดเวลา ชื่อนี้แก่ตัวได้อย่างเหมาะเจาะ สิ่งที่ตลาดเทรดจริงสอน เรียงตามลำดับต้นทุน:

1. **เงินทุนที่แตกกระจายทำให้เกิดภาวะล็อกตาย** ยอดคงเหลือก้อนเล็กที่กระจายไปหลายบัญชีย่อย
   โดยแต่ละบัญชีมีคำสั่งค้างอยู่ ทำให้ยอดคงเหลืออิสระเหลือศูนย์
2. **ค่าผ่านทางไม่ใช่รายละเอียดเล็ก ๆ** ค่าธรรมเนียมและสลิปเพจหักล้าง edge ที่ backtest
   แสดงว่าเหลือเฟือ อย่างเงียบ ๆ
3. **บอททุกตัวที่ประกาศทั้งบัญชีจะทวีคูณความเสี่ยงเป็น N เท่า** เจ็ดบอท × 2% = 14%
4. **การเฝ้าระวังที่ไม่มีสถานะคือความล้มเหลวแบบเงียบ** การข้าม tick 1,486 ครั้งดูเหมือน
   "ไม่มีอะไรเกิดขึ้น" อยู่นานหลายชั่วโมง เพราะไม่มีสถานะใดบอกว่า "ฉันไม่มีเงินทุน"
5. **คำสั่งที่ไม่ได้ติดตามหลัง crash คือเงินที่มองไม่เห็น** จึงต้องมี idempotency key
6. **เทเลเมตรีที่อ่านแล้วเหมือนฟอสซิลยังแย่กว่าไม่มีเทเลเมตรีเลย** ไฟล์ health ที่เก่าค้าง
   จะถูกนับว่า "ทำงานอยู่" เว้นแต่มีอะไรบางอย่างตรวจอายุของมันอย่างชัดเจน
7. **พาธในระบบผลิตคลาดเคลื่อนแล้วพังหมดพร้อมกัน** สิบจากสิบสอง unit ที่พังมีสาเหตุราก
   เดียวกัน: พาธโปรเจกต์ที่เก่าค้างใน unit ของ systemd และใน crontab ที่ไม่เคยถูก version ไว้

## 🛠 เริ่มต้นอย่างรวดเร็ว

```bash
git clone git@github.com:grivetto/alpha-omega-trading.git
cd alpha-omega-trading
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env         # credentials stay local: never commit secrets

# integrity check of the machine (read-only, exit code 1 on alarm)
python tools/fleet_integrity.py
python tools/fleet_integrity.py --host nuvola --host MARCODG1 --host mc2

# tests
python -m pytest denaro/tests -q

# a node
python -m denaro.denaro_node --config config/node_nuvola_trade.yaml

# honest backtest against real fees
python -m denaro.backtest --config config/node_nuvola_trade.yaml --days 60 --fee 0.0035
```

## 🚧 งานที่ยังเปิดอยู่ เรียงตามคุณค่า

1. **บันทึก position ของ grid เมื่อมี fill** ความล้มเหลวของ test จริงรายการสุดท้ายที่เหลืออยู่:
   grid ซื้อ, fill ไม่ถูกบันทึกเป็น position ที่เปิดอยู่, และ stop ก็ต้องอนุมานย้อนกลับจาก
   คำสั่งขาย ถูกต้อง แต่ยังไม่เพียงพอ
2. **การแยกขอบเขตของ test** test หนึ่งผ่านเมื่อรันเดี่ยว ๆ แต่ fail ในชุดทดสอบ → มี state
   ที่ใช้ร่วมกันระหว่าง test ที่เกี่ยวข้อง: `pytest-asyncio` ไม่ได้ติดตั้ง และ `asyncio_mode`
   เป็น option ที่ไม่รู้จัก ดังนั้น test แบบ async ในตอนนี้จึงรันผ่านกลไกที่ยังอธิบายไม่ได้
3. **เทเลเมตรี** — 4 units รีสตาร์ทวนผิดปกติ ทั้งหมดมาจากพาธ `~/denaro`
   กับ `~/alpha-omega-trading` ที่คลาดเคลื่อนกัน
4. **ทำ version ให้โครงสร้างพื้นฐาน** (`deploy/systemd/`, `deploy/cron/` พร้อม `PROJECT_ROOT`
   ที่รับพารามิเตอร์ได้): สาเหตุรากของ 10 จาก 12 unit ที่พัง และของความมืดบอดเรื่องว่า
   ใครแก้อะไร
5. **เงินทุน** ตัวแปรที่ชี้ขาด และถูกแยกออกจากโค้ดโดยตั้งใจ

## 🗺 เส้นทางการขยาย

โครงสร้างเหมือนกันทุกระดับขนาด: **หนึ่งโหนด = หนึ่งกลยุทธ์ = หนึ่งบัญชี** สิ่งที่เปลี่ยนคือ
*จำนวนโหนด* ไม่ใช่จำนวนกลยุทธ์ที่ยัดลงในบัญชีเดียว การยัดรวมกันคือการทดลองที่ทำไปแล้ว —
และมันให้ผลเป็นความเสี่ยงรวม 14%, บอทหยุดกันเองเพราะใช้ equity ร่วมกัน, และ stop ตัวหนึ่ง
เทขายสินค้าคงคลังของบอทอีกตัว

- [x] **ตอนนี้:** ที่เก็บเรียบร้อย ข้อบกพร่องร้ายแรงสามข้อปิดพร้อมหลักฐาน การตรวจสอบ
      ความสมบูรณ์ใช้งานได้ ชุดทดสอบรันได้
- [ ] **ถัดไป:** บันทึก fill ของ grid, การแยกขอบเขตของ test, ซ่อมเทเลเมตรี, ทำ version
      ให้โครงสร้างพื้นฐาน
- [ ] **หลังจากนั้น:** ประตูค่าธรรมเนียม — ทำให้บัญชี **หนึ่ง** บัญชีอยู่ในสถานะที่สะอาด
      แล้วยื่นขออัปเกรดเป็นดิริเวทีฟ มันไม่กระทบการ deploy ใด ๆ ย้อนกลับได้ และเป็น
      การดำเนินการเดียวที่ปลดล็อกความถี่
- [ ] **หลังจากนั้น:** เพิ่มเงินทุนเป็นขั้น และเฉพาะเมื่อมีหลักฐานนอกตัวอย่าง (out-of-sample)
      เท่านั้น

## ⚖️ ข้อจำกัดความรับผิด

**ซอฟต์แวร์นี้เผยแพร่เพื่อวัตถุประสงค์ทางการศึกษา ทางวิชาการ และทางการวิจัยเท่านั้น
ไม่ใช่คำแนะนำทางการเงินหรือการลงทุน** การซื้อขายคริปโตเคอร์เรนซีแบบอัลกอริทึมมีความเสี่ยง
ทางการเงินอย่างมีนัยสำคัญ รวมถึงความเป็นไปได้ที่จะสูญเสียเงินลงทุนทั้งหมด ผู้เขียนไม่ให้
คำรับรองหรือการรับประกันใด ๆ เกี่ยวกับความสามารถในการทำกำไรหรือผลการดำเนินงานของระบบ
ห้ามเทรดด้วยเงินทุนที่คุณรับการสูญเสียไม่ได้เด็ดขาด
